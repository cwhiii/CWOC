# Requirements Document

## Introduction

This feature adds a Templates system to CWOPOD that lets users save reusable print and typeset configurations and apply them to book projects. Templates are first-class entities that live alongside books, accessible via a new "Templates" tab on the Projects/Bookshelf page. A template stores the six physical book settings (trim_size, paper_type, color_interior, cover_finish, binding_type, font_size) and uses a fixed sample text ("The Enchanted Castle" by E. Nesbit from Project Gutenberg) for preview rendering. Users can create templates from scratch via a simplified wizard, create them from existing book settings, and apply them to any book project to enforce consistent physical specs across a series.

## Glossary

- **Template**: A named, reusable configuration storing six print/typeset settings (trim_size, paper_type, color_interior, cover_finish, binding_type, font_size) that can be applied to one or more book projects
- **Template_Builder**: A simplified wizard for creating or editing templates, using fixed sample text and consisting of three steps: Print Size, Print Options, and Typeset
- **Sample_Text**: The fixed preview text used by all templates, sourced from "The Enchanted Castle" by E. Nesbit via Project Gutenberg
- **Bookshelf_Page**: The Projects/Bookshelf page that displays the user's collection, now with two tabs: Books and Templates
- **Template_Tab**: The tab on the Bookshelf_Page that lists all of the user's saved templates
- **Print_Settings**: The collective set of six physical book configuration fields: trim_size, paper_type, color_interior, cover_finish, binding_type, font_size
- **Typeset_PDF**: The interior PDF generated by the Typst typesetting engine, used for preview in the Template_Builder and as the final interior for book projects
- **Apply_Template**: The action of overwriting a book project's Print_Settings with the values stored in a template
- **Invalidation_Warning**: A confirmation dialog shown when applying a template would change trim_size or font_size on a book that already has a Typeset_PDF, indicating the book will need re-typesetting

## Requirements

### Requirement 1: Template Data Model

**User Story:** As a user, I want templates to store all physical book settings with a user-chosen name, so that I can identify and reuse my configurations.

#### Acceptance Criteria

1. THE Template SHALL store the following required fields: name (string, 1–100 characters), trim_size (one of: 5x8, 5.06x7.81, 5.25x8, 5.5x8.5, 6x9, 8.5x11), paper_type (one of: white, cream), color_interior (boolean), cover_finish (one of: glossy, matte), binding_type (one of: paperback, hardback, micro), and font_size (one of: 9pt, 10pt, 11pt, 12pt, 13pt, 14pt); all six Print_Settings fields SHALL be non-null
2. THE Template SHALL be scoped to the owning user; users SHALL NOT access templates belonging to other users
3. THE Template SHALL store a reference to its preview Typeset_PDF path generated from the Sample_Text; this field SHALL be null until a preview is generated
4. THE Template SHALL record created_at and updated_at timestamps that are set automatically on creation and modification respectively
5. THE System SHALL allow a user to save an unlimited number of templates
6. IF a Template field value does not match the allowed set for that field, THEN THE System SHALL reject the save and return a validation error indicating which field has an invalid value

### Requirement 2: Templates Tab on Bookshelf Page

**User Story:** As a user, I want to see my templates alongside my books on the Bookshelf page, so that I can manage them from a familiar location.

#### Acceptance Criteria

1. THE Bookshelf_Page SHALL display two tabs: "Books" (the existing bookshelf, active by default) and "Templates"
2. WHEN the user selects the Template_Tab, THE Bookshelf_Page SHALL display all of the user's saved templates as a list showing each template's name, trim_size, and binding_type
3. THE Template_Tab SHALL provide a "New Template" button that navigates to the Template_Builder
4. THE Template_Tab SHALL provide a "Create from Book..." button that opens a picker to select an existing book project
5. WHEN the user clicks a template in the list, THE Bookshelf_Page SHALL navigate to the Template_Builder pre-loaded with that template's settings for editing
6. THE Template_Tab SHALL provide a delete action for each template that displays a confirmation dialog before removing the template, and upon confirmed deletion SHALL remove the template from the list and display a success message
7. IF the user has no saved templates, THEN THE Template_Tab SHALL display an empty state message and the "New Template" and "Create from Book..." buttons

### Requirement 3: Template Builder Wizard

**User Story:** As a user, I want a simplified wizard to configure my template settings and preview how they look rendered, so that I can fine-tune my physical book specs visually.

#### Acceptance Criteria

1. THE Template_Builder SHALL present a three-step wizard with steps in this order: Print Size, Print Options, and Typeset, allowing the user to navigate forward and backward between completed steps
2. THE Template_Builder SHALL use the Sample_Text ("The Enchanted Castle" by E. Nesbit from Project Gutenberg) as fixed content for all preview rendering
3. THE Template_Builder SHALL NOT include Source, Typo Check, Cover, or Print/Order steps
4. WHEN the user reaches the Typeset step, THE Template_Builder SHALL trigger a Celery background task to generate a preview Typeset_PDF using the current Print_Settings and the Sample_Text via the existing Typst typesetting pipeline, displaying a spinner until the task completes
5. THE Template_Builder SHALL provide a "Save Template" action on the Typeset step that is enabled only after a preview Typeset_PDF has been successfully generated, and that persists the current Print_Settings and the generated preview Typeset_PDF
6. WHEN saving a new template, THE Template_Builder SHALL prompt the user to enter a name for the template
7. WHEN editing an existing template, THE Template_Builder SHALL pre-populate all steps with the template's current Print_Settings
8. IF the Typeset_PDF generation task fails, THEN THE Template_Builder SHALL display an error message indicating the failure reason and provide a "Retry" button to re-trigger generation

### Requirement 4: Template Creation from Existing Book

**User Story:** As a user, I want to create a template from an existing book's settings, so that I can quickly capture a configuration I already like.

#### Acceptance Criteria

1. WHEN the user clicks "Create from Book..." on the Template_Tab, THE System SHALL display a picker listing all of the user's book projects with their titles, sorted alphabetically by title
2. IF the user has no book projects, THEN THE System SHALL disable the "Create from Book..." button on the Template_Tab
3. WHEN the user selects a book from the picker, THE System SHALL create a new unsaved template pre-populated with that book's current Print_Settings (trim_size, paper_type, color_interior, cover_finish, binding_type, font_size), resolving any null field by substituting the user's corresponding default preference value
4. IF both a book's Print_Settings field is null AND the user's corresponding default preference value is null, THEN THE System SHALL use the system-wide default value for that field when populating the new template
5. WHEN the user dismisses the picker without selecting a book, THE System SHALL close the picker and return to the Template_Tab with no template created
6. WHEN the System has resolved all six Print_Settings values for the new template, THE System SHALL navigate to the Template_Builder with the new template loaded in unsaved state, allowing the user to preview, adjust, and name the template before saving

### Requirement 5: Apply Template to Book

**User Story:** As a user, I want to apply a template to a book project, so that all its print settings match my series configuration.

#### Acceptance Criteria

1. THE Project page SHALL provide an "Apply Template" button in the Print Options section
2. WHEN the user clicks "Apply Template", THE System SHALL display a picker listing all of the user's saved templates with their names and Print_Settings summaries
3. IF the user has no saved templates WHEN the picker is displayed, THEN THE System SHALL show an empty state message indicating no templates are available and providing guidance to create one
4. WHEN the user selects a template from the picker, THE System SHALL overwrite all six Print_Settings fields (trim_size, paper_type, color_interior, cover_finish, binding_type, font_size) on the target book project with the values from the selected template and update the Print Options section to reflect the new values
5. IF the selected template's trim_size or font_size differs from the book's current values AND the book has an existing Typeset_PDF, THEN THE System SHALL display the Invalidation_Warning before applying
6. THE Invalidation_Warning SHALL inform the user that applying the template will require re-typesetting the book and present "Confirm" and "Cancel" actions
7. IF the user cancels the Invalidation_Warning, THEN THE System SHALL close the dialog and leave the book's Print_Settings and Typeset_PDF unchanged
8. WHEN the user confirms the Invalidation_Warning, THE System SHALL apply the template settings, clear the book's existing Typeset_PDF path and page_count, and reset the book's typeset state

### Requirement 6: Sample Text Management

**User Story:** As a user, I want the template preview to always use the same sample book, so that I can compare templates against a consistent reference.

#### Acceptance Criteria

1. THE System SHALL use "The Enchanted Castle" by E. Nesbit (Project Gutenberg ID 3536) as the Sample_Text for all template previews
2. WHEN the Template_Builder generates a preview and the Sample_Text is not already cached locally, THE System SHALL download the Sample_Text using the existing Gutenberg provider and normalize it via the standard Pandoc pipeline before caching
3. IF the Sample_Text download fails due to network error or provider unavailability, THEN THE System SHALL display an error message indicating the sample book could not be retrieved and block preview generation until the download succeeds on a subsequent attempt
4. THE Sample_Text SHALL be stored once per installation at a shared location within the configured storage_path and reused across all users and templates without re-downloading
5. THE System SHALL NOT expose any user-facing control to change or override the Sample_Text used for template previews

### Requirement 7: Template Backend API

**User Story:** As a developer, I want REST API endpoints for template CRUD and application, so that the frontend can manage templates.

#### Acceptance Criteria

1. THE Backend SHALL provide `GET /api/templates` that returns all templates for the authenticated user, including id, name, Print_Settings, preview_pdf_path, created_at, and updated_at, ordered by updated_at descending, with a maximum of 50 templates returned
2. THE Backend SHALL provide `POST /api/templates` that creates a new template with the provided name (1 to 100 characters, trimmed of leading/trailing whitespace) and Print_Settings, validates all Print_Settings values, and returns the created template
3. THE Backend SHALL provide `GET /api/templates/{template_id}` that returns a single template's full details after verifying the authenticated user owns the template
4. THE Backend SHALL provide `PATCH /api/templates/{template_id}` that updates a template's name or Print_Settings after verifying ownership, validates any provided Print_Settings values, and returns the updated template
5. THE Backend SHALL provide `DELETE /api/templates/{template_id}` that removes a template after verifying ownership and returns a confirmation response with the deleted template's id
6. THE Backend SHALL provide `POST /api/projects/{project_id}/apply-template` that accepts a template_id, validates ownership of both the template and project, and overwrites the project's Print_Settings fields with all non-null values from the template's Print_Settings, leaving project fields unchanged for any template field that is null
7. THE Backend SHALL provide `POST /api/templates/from-book` that accepts a project_id and a template name (1 to 100 characters), verifies ownership of the project, and creates a new template pre-populated with that book's effective Print_Settings (per-book values with user defaults as fallback for nulls)
8. THE Backend SHALL validate all Print_Settings values against the same allowed sets used by the existing print-options endpoint: trim_size in {5x8, 5.06x7.81, 5.25x8, 5.5x8.5, 6x9, 8.5x11}, paper_type in {white, cream}, cover_finish in {glossy, matte}, binding_type in {paperback, hardback, micro}, font_size in {9pt, 10pt, 11pt, 12pt, 13pt, 14pt}
9. IF a template or project referenced by template_id or project_id does not exist or is not owned by the authenticated user, THEN THE Backend SHALL return HTTP 404 with an error message indicating the resource was not found
10. IF a `POST /api/templates` or `PATCH /api/templates/{template_id}` request contains a Print_Settings value that fails validation, THEN THE Backend SHALL return HTTP 422 with an error message indicating which field is invalid and the allowed values

### Requirement 8: Template Preview PDF Generation

**User Story:** As a user, I want to see a rendered PDF preview of my template settings, so that I can evaluate how the physical book will look before applying the template to real projects.

#### Acceptance Criteria

1. WHEN the user reaches the Typeset step in the Template_Builder, THE System SHALL trigger a Celery background task to generate a Typeset_PDF using the template's Print_Settings and the Sample_Text
2. THE System SHALL use the same Typst typesetting pipeline used for book projects to generate the template preview Typeset_PDF
3. WHEN the preview generation task completes successfully, THE Template_Builder SHALL display the rendered PDF inline for the user to review, using the same PDF viewer component used for book project previews
4. THE System SHALL store the generated preview Typeset_PDF at a path associated with the template for future reference
5. WHEN the user modifies Print_Settings after a preview has been generated and returns to the Typeset step, THE System SHALL regenerate the preview Typeset_PDF with the updated settings
6. IF the preview generation task fails, THEN THE Template_Builder SHALL display an error message indicating the cause of the failure and provide the user with the option to retry generation
7. IF a preview generation task is already in progress for the current template, THEN THE System SHALL not trigger a second concurrent task and SHALL continue displaying the in-progress status of the existing task

### Requirement 9: Template Name Validation

**User Story:** As a user, I want clear feedback when naming my templates, so that I can identify them easily in my collection.

#### Acceptance Criteria

1. THE System SHALL trim leading and trailing whitespace from the template name before validation
2. THE System SHALL require a template name that contains at least 1 non-whitespace character when saving a template
3. THE System SHALL allow template names up to 100 characters in length (measured after trimming)
4. THE System SHALL allow duplicate template names within the same user's collection (users may want variations like "Trade Paperback v1" and "Trade Paperback v2")
5. WHEN the user attempts to save a template with an empty or whitespace-only name, THE System SHALL display an inline validation error indicating a name is required and prevent saving
6. IF the user enters a template name that exceeds 100 characters after trimming, THEN THE System SHALL display an inline validation error indicating the maximum length and prevent saving
