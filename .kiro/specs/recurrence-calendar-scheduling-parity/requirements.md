# Requirements Document

## Introduction

This spec covers the implementation of 26 missing or partially-implemented web functions on the Android app, all related to recurrence management, calendar view enhancements, and scheduling features. The goal is full parity: the Android app must produce the same user-facing outcomes as the web version for each function. The functions are grouped into 11 logical areas spanning recurrence series actions, delete scope options, calendar view modes, perpetual date mode, default notifications, cron expressions, quick alert creation, alert settings, period filtering, and project child management.

## Glossary

- **Chit**: The core data record in CWOC — a flexible item that can serve as a task, note, event, alarm, checklist, or project.
- **Recurring_Chit**: A chit with a `recurrence_rule` that generates virtual instances on a schedule.
- **Virtual_Instance**: A computed occurrence of a Recurring_Chit that does not have its own database record until broken off or modified.
- **Recurrence_Exception**: A date entry in `recurrence_exceptions` that marks a Virtual_Instance as broken off, deleted, or modified.
- **Series**: The complete set of Virtual_Instances generated by a Recurring_Chit's recurrence rule.
- **Break_Off**: The action of converting a Virtual_Instance into a standalone Chit with its own database record.
- **RecurrenceEngine**: The Android domain class responsible for expanding recurrence rules into Virtual_Instances.
- **CalendarViewModel**: The Android ViewModel managing calendar view state (mode, visible date range, events).
- **ChitEditorViewModel**: The Android ViewModel managing chit editor state (fields, zones, save logic).
- **DateZone**: The editor UI section for configuring a chit's date mode (due, start/end, perpetual) and related date/time fields.
- **AlertsZone**: The editor UI section for managing a chit's alarms, notifications, timers, and stopwatches.
- **Quick_Alert_Sheet**: A bottom sheet accessible from any screen for rapidly creating alarms, timers, stopwatches, or reminders.
- **Cron_Expression**: A scheduling expression (minute, hour, day-of-month, month, day-of-week) used by the rules engine for time-based triggers.
- **TimePeriodDropdown**: The Android sidebar component for selecting the active time period filter (Day, Week, Month, Quarter, Year, All).
- **ChitPickerSheet**: An existing Android bottom sheet composable for searching and selecting chits.
- **ProjectsZone**: The editor UI section for managing a chit's project relationships (parent, children).
- **SettingsEntity**: The Room entity storing synced user settings on Android.
- **All_Day_Section**: The calendar view area displaying events that span entire days, rendered above the time grid.
- **X_Day_View**: A configurable calendar view showing between 1 and 7 days (intermediate between Day and Week views).
- **Perpetual_Mode**: A date mode indicating a chit started on a specific date with no end date (ongoing indefinitely).
- **Default_Notifications**: User-configured notification presets that auto-populate when a date mode is first assigned to a chit.
- **Combine_Alerts**: A visual indicator setting that, when enabled, shows a single bell icon instead of individual alert-type icons on chit cards.
- **Enabled_Periods**: A user setting specifying which time periods (Day, Week, Month, Quarter, Year, All) appear in the TimePeriodDropdown.

## Requirements

### Requirement 1: Recurrence Series Information Computation

**User Story:** As a user viewing a recurring chit instance, I want to see series statistics (instance number, total count, completion rate), so that I understand my progress within the series.

**Covers:** W95 `getRecurrenceSeriesInfo`

#### Acceptance Criteria

1. WHEN a user opens a Virtual_Instance, THE RecurrenceEngine SHALL compute the instance's ordinal position within the Series, the total number of past instances, the count of completed instances, and the completion success rate.
2. THE RecurrenceEngine SHALL account for Recurrence_Exceptions (broken-off, deleted, completed) when computing series statistics.
3. WHEN the Recurring_Chit has no end date, THE RecurrenceEngine SHALL compute statistics based on instances from the start date through the current date.

---

### Requirement 2: Recurrence Series Summary UI

**User Story:** As a user, I want to see a visual summary of all instances in a recurring series with their completion status, so that I can quickly assess the series at a glance.

**Covers:** W96 `_renderSeriesSummary`

#### Acceptance Criteria

1. WHEN a user views series information for a Recurring_Chit, THE Android_App SHALL display a scrollable list of all Virtual_Instances with their dates and completion status (pending, completed, broken off, deleted).
2. THE Android_App SHALL visually distinguish between completed, pending, broken-off, and deleted instances using distinct icons or colors.
3. WHEN the Series contains more instances than fit on screen, THE Android_App SHALL provide scrollable access to the full list.

---

### Requirement 3: Complete Series Action

**User Story:** As a user, I want to mark an entire recurring series as complete in one action, so that I do not have to complete each instance individually.

**Covers:** W97 `_recurrenceCompleteSeries`

#### Acceptance Criteria

1. WHEN a user selects "Complete Series" on a Recurring_Chit, THE Android_App SHALL set the Recurring_Chit's status to Complete.
2. WHEN "Complete Series" is executed, THE Android_App SHALL persist the status change and sync it to the server.
3. THE Android_App SHALL present the "Complete Series" action in the recurrence action modal or quick-edit context.

---

### Requirement 4: Break Off Instance Action

**User Story:** As a user, I want to break off a single recurring instance into a standalone chit, so that I can modify it independently without affecting the rest of the series.

**Covers:** W98 `_recurrenceBreakOff`

#### Acceptance Criteria

1. WHEN a user selects "Break Off Instance" on a Virtual_Instance, THE Android_App SHALL create a new standalone Chit with the Virtual_Instance's date, time, and inherited fields from the parent Recurring_Chit.
2. WHEN a Break_Off is executed, THE Android_App SHALL add a Recurrence_Exception for that date to the parent Recurring_Chit so the Virtual_Instance no longer appears in the series.
3. WHEN the new standalone Chit is created, THE Android_App SHALL navigate the user to the editor for the new Chit.

---

### Requirement 5: Recurrence Auto-Archive

**User Story:** As a user, I want recurring chits to auto-archive when all instances up to the end date are completed or broken off, so that finished series do not clutter my active views.

**Covers:** W99 `_checkRecurrenceAutoArchive`

#### Acceptance Criteria

1. WHEN all Virtual_Instances of a Recurring_Chit up to its end date are completed or broken off, THE Android_App SHALL automatically archive the Recurring_Chit.
2. THE Android_App SHALL check the auto-archive condition after any completion or break-off action on a Virtual_Instance.
3. WHEN a Recurring_Chit has no end date, THE Android_App SHALL not trigger auto-archive (perpetual series cannot be fully completed).

---

### Requirement 6: Instance Banner Display

**User Story:** As a user viewing a recurring instance, I want to see a banner indicating this is an instance of a series with relevant context, so that I know I am looking at a virtual occurrence rather than a standalone chit.

**Covers:** W314 `_showInstanceBanner(dateStr)`

#### Acceptance Criteria

1. WHEN a user opens a Virtual_Instance in the editor or quick-edit view, THE Android_App SHALL display a banner indicating the item is instance N of the series, with the instance date.
2. THE banner SHALL include a link or action to view the parent Recurring_Chit.
3. THE banner SHALL be visually distinct from the chit content (e.g., a colored strip at the top of the editor).

---

### Requirement 7: Save Instance Exception

**User Story:** As a user, I want to save modifications to a single recurring instance without affecting the rest of the series, so that I can customize individual occurrences.

**Covers:** W315 `_saveInstanceException(dateStr)`

#### Acceptance Criteria

1. WHEN a user modifies a Virtual_Instance and saves, THE Android_App SHALL create a Recurrence_Exception for that date with the modified data.
2. THE Android_App SHALL persist the exception to the parent Recurring_Chit's `recurrence_exceptions` field and sync it to the server.
3. WHEN the exception is saved, THE RecurrenceEngine SHALL use the exception data instead of the parent's data when expanding that date.

---

### Requirement 8: Recurring Drag Modal

**User Story:** As a user, I want to be prompted with scope options when I drag a recurring event to a new time on the calendar, so that I can choose whether the change applies to one instance, this and future, or all instances.

**Covers:** W368 `_showRecurringDragModal(parentId, dateStr, newTimes, virtualChit)`

#### Acceptance Criteria

1. WHEN a user drags a Virtual_Instance to a new time slot on the calendar, THE Android_App SHALL display a modal asking whether to apply the change to "This instance only," "This and all future," or "All instances."
2. WHEN "This instance only" is selected, THE Android_App SHALL create a Recurrence_Exception with the new time for that date.
3. WHEN "This and all future" is selected, THE Android_App SHALL update the Recurring_Chit's recurrence rule or times starting from that date forward.
4. WHEN "All instances" is selected, THE Android_App SHALL update the Recurring_Chit's time fields directly.

---

### Requirement 9: Recurrence Action Modal

**User Story:** As a user, I want a dedicated modal presenting all available recurrence actions (complete series, break off, view series info), so that I can manage recurring chits efficiently.

**Covers:** W685 `showRecurrenceActionModal(chit, onRefresh)`

#### Acceptance Criteria

1. WHEN a user long-presses or selects the recurrence action on a Recurring_Chit or Virtual_Instance, THE Android_App SHALL display a modal with actions: "View Series Info," "Complete Series," "Break Off Instance," and "Delete" (with scope options).
2. WHEN an action is selected, THE Android_App SHALL execute the corresponding operation and refresh the calling view.
3. THE modal SHALL only show actions applicable to the current context (e.g., "Break Off Instance" only appears for Virtual_Instances, not the parent chit itself).

---

### Requirement 10: Recurrence-Aware Delete Options

**User Story:** As a user, I want delete options that respect recurrence scope (this instance, this and future, entire series), so that deleting a recurring instance does not destroy the whole series.

**Covers:** W684 `_showDeleteSubMenu(...)`

#### Acceptance Criteria

1. WHEN a user deletes a Virtual_Instance, THE Android_App SHALL display a submenu with options: "Delete this instance only," "Delete this and all future," and "Delete entire series."
2. WHEN "Delete this instance only" is selected, THE Android_App SHALL add a Recurrence_Exception marking that date as deleted, without affecting other instances.
3. WHEN "Delete this and all future" is selected, THE Android_App SHALL set an `until` date on the recurrence rule to terminate the series before the selected instance.
4. WHEN "Delete entire series" is selected, THE Android_App SHALL soft-delete the parent Recurring_Chit.
5. WHEN deleting a non-recurring chit, THE Android_App SHALL show a simple delete confirmation without recurrence scope options.

---

### Requirement 11: All-Day Events Height Cap

**User Story:** As a user viewing the calendar, I want the all-day events section to be height-capped with a "show more" toggle, so that many all-day events do not push the time grid off-screen.

**Covers:** W195 `_addAllDayHeightCap(eventsRow, container)`

#### Acceptance Criteria

1. WHEN the All_Day_Section contains more events than fit within a maximum height threshold, THE Android_App SHALL cap the section height and display a "show more" toggle.
2. WHEN the user taps "show more," THE Android_App SHALL expand the All_Day_Section to reveal all events.
3. WHEN the All_Day_Section is expanded, THE Android_App SHALL display a "show less" toggle to collapse it back to the capped height.
4. THE height cap SHALL default to showing a maximum of 3 all-day event rows before requiring expansion.

---

### Requirement 12: Configurable X-Day Calendar View

**User Story:** As a user, I want to configure the calendar to show any number of days between 1 and 7, so that I can use a 2-day, 3-day, or 5-day view instead of only Day or Week.

**Covers:** W245 `_weekViewDayOffset`

#### Acceptance Criteria

1. THE CalendarViewModel SHALL support a configurable day count between 1 and 7 for the X_Day_View mode.
2. WHEN the user selects an X_Day_View, THE Android_App SHALL display exactly the configured number of days starting from the current day offset.
3. THE Android_App SHALL provide a UI control (in calendar view settings or a long-press on the view mode selector) to set the number of visible days.
4. THE Android_App SHALL persist the X_Day_View day count preference across sessions.

---

### Requirement 13: Perpetual Mode Toggle

**User Story:** As a user editing a chit, I want to set it to "Perpetual" date mode (started on a date, no end), so that I can track ongoing items that have a start but no planned completion.

**Covers:** W198 `onPerpetualToggle()`

#### Acceptance Criteria

1. THE DateZone mode selector SHALL include "Perpetual" as a date mode option alongside Due, Start/End, and None.
2. WHEN the user selects Perpetual mode, THE ChitEditorViewModel SHALL set the chit's `perpetual` field to true and set the start date to today if no start date exists.
3. WHEN Perpetual mode is activated, THE ChitEditorViewModel SHALL clear any end date on the chit.
4. WHEN the user switches away from Perpetual mode, THE ChitEditorViewModel SHALL set the `perpetual` field to false.

---

### Requirement 14: Perpetual Date Formatting

**User Story:** As a user viewing a perpetual chit, I want to see a formatted display like "Since January 15, 2024," so that the perpetual start date is clearly communicated.

**Covers:** W199 `_fmtPerpetualDate()`

#### Acceptance Criteria

1. WHEN a chit has `perpetual` set to true and a start date, THE Android_App SHALL display the start date formatted as "Since [full month name] [day], [year]" (e.g., "Since January 15, 2024").
2. THE perpetual date display SHALL appear in the DateZone section of the editor and on chit cards where date information is shown.
3. WHEN a perpetual chit has no start date, THE Android_App SHALL display "Perpetual (no start date)" as a fallback.

---

### Requirement 15: Apply Default Notifications on Date Mode Activation

**User Story:** As a user, I want my configured default notifications to auto-populate when I first assign a date mode to a chit, so that I do not have to manually add the same notifications every time.

**Covers:** W202 `_applyDefaultNotifications(mode)`

#### Acceptance Criteria

1. WHEN a date mode (due, start/end, perpetual) is first assigned to a chit that previously had no date mode, THE ChitEditorViewModel SHALL read the user's `default_notifications` setting from SettingsEntity.
2. WHEN default notifications exist for the activated mode, THE ChitEditorViewModel SHALL auto-populate the chit's alerts list with those notification presets.
3. THE Android_App SHALL not overwrite existing alerts if the chit already has manually-configured notifications.
4. WHEN the `default_notifications` setting is empty or not configured, THE Android_App SHALL not add any alerts automatically.

---

### Requirement 16: Human-Readable Cron Description

**User Story:** As a user configuring a rule trigger, I want to see a human-readable description of the cron expression, so that I can verify the schedule without interpreting raw cron syntax.

**Covers:** W250 `_describeCron(expr)`

#### Acceptance Criteria

1. WHEN a cron expression is entered or assembled in the rule editor, THE Android_App SHALL display a human-readable description (e.g., "At 9:00 AM, Monday through Friday").
2. THE description SHALL update in real-time as the user modifies cron fields.
3. THE description SHALL handle all standard cron features: specific values, ranges, lists, wildcards, and step values.

---

### Requirement 17: Visual Cron Expression Builder

**User Story:** As a user, I want to build cron expressions through a visual UI with dropdowns and selectors, so that I do not need to know cron syntax.

**Covers:** W251 `_assembleCronExpression()`

#### Acceptance Criteria

1. THE Android_App SHALL provide a visual cron builder with selectable inputs for minute, hour, day-of-month, month, and day-of-week fields.
2. WHEN the user selects values in the builder inputs, THE Android_App SHALL assemble a valid cron expression string from those selections.
3. THE builder SHALL support common patterns: specific values, ranges (e.g., Mon-Fri), lists (e.g., 1,15), wildcards (*), and step values (e.g., */5).
4. THE assembled cron expression SHALL be stored in the rule's trigger configuration.

---

### Requirement 18: Cron Expression Validation

**User Story:** As a user, I want cron expressions to be validated with clear error messages, so that I know immediately if my schedule configuration is invalid.

**Covers:** W252 `_validateCronExpression(expr)`

#### Acceptance Criteria

1. WHEN a cron expression is entered or assembled, THE Android_App SHALL validate it for correctness (proper field count, valid ranges per field, valid special characters).
2. IF a cron expression is invalid, THEN THE Android_App SHALL display a user-friendly error message identifying which field is invalid and why.
3. THE Android_App SHALL prevent saving a rule with an invalid cron expression.

---

### Requirement 19: Quick Alert Bottom Sheet — Open and Type Selection

**User Story:** As a user on any screen, I want to quickly create an alarm, timer, stopwatch, or reminder without navigating to the editor, so that I can set alerts with minimal friction.

**Covers:** W113 `_openQuickAlertModal()`, W114 `_closeQuickAlertModal()`, W115 `_quickAlertShowEditor(type)`

#### Acceptance Criteria

1. THE Android_App SHALL provide a Quick_Alert_Sheet accessible from the main FAB or a dedicated action button on any primary screen.
2. WHEN the Quick_Alert_Sheet opens, THE Android_App SHALL display type selection options: Alarm, Timer, Stopwatch, and Reminder.
3. WHEN the user selects a type, THE Quick_Alert_Sheet SHALL transition to show the editor fields appropriate for that alert type.
4. THE Quick_Alert_Sheet SHALL be dismissible by swiping down, tapping outside, or pressing a close button.

---

### Requirement 20: Quick Alert Save and Confirmation

**User Story:** As a user, I want to save a quick alert and see confirmation, so that I know the alert was created successfully.

**Covers:** W116 `_quickAlertSave(type, data, andView, autoStart)`, W117 `_quickReminderSave(data, andView)`, W118 `_quickAlertJumpToIndependent()`, W119 `_showQuickAlertToast(type)`

#### Acceptance Criteria

1. WHEN the user completes the quick alert form and taps Save, THE Android_App SHALL create the alert (either as an independent alert or as a chit with a notification, depending on type).
2. WHEN a quick alert is saved successfully, THE Android_App SHALL display a confirmation toast indicating the alert type and that it was created.
3. THE Quick_Alert_Sheet SHALL provide a "Save & View" option that saves the alert and navigates to the Alerts tab showing the new alert.
4. WHEN creating a Timer or Stopwatch, THE Quick_Alert_Sheet SHALL provide an "Auto-Start" toggle that starts the timer/stopwatch immediately upon save.
5. THE Quick_Alert_Sheet SHALL provide a "Jump to Alarms" action that navigates to the Alerts tab in independent mode.

---

### Requirement 21: Toggle Combine Alerts Setting

**User Story:** As a user, I want to toggle the "Combine Alerts" visual indicator setting from the Android app, so that I can control whether alert icons are shown individually or as a single bell icon on chit cards.

**Covers:** W218 `_toggleCombineAlerts()`

#### Acceptance Criteria

1. THE Android_App SHALL display a "Combine Alerts" toggle in Settings under the Visual Indicators section.
2. WHEN the user toggles "Combine Alerts" on, THE Android_App SHALL update the `combine_alerts` setting in SettingsEntity and sync it to the server.
3. WHEN "Combine Alerts" is enabled, THE Android_App SHALL display a single bell icon on chit cards instead of individual alert-type icons.
4. WHEN "Combine Alerts" is disabled, THE Android_App SHALL display individual icons for each alert type (alarm, notification, timer, stopwatch).

---

### Requirement 22: Filter Period Dropdown by Enabled Periods

**User Story:** As a user, I want the time period dropdown to only show periods I have enabled in settings, so that unused period options do not clutter the selector.

**Covers:** W395 `_applyEnabledPeriods()`

#### Acceptance Criteria

1. WHEN the TimePeriodDropdown is rendered, THE Android_App SHALL read the `enabled_periods` setting from SettingsEntity.
2. THE TimePeriodDropdown SHALL only display period options that are included in the `enabled_periods` list.
3. WHEN `enabled_periods` is empty or not set, THE TimePeriodDropdown SHALL display all period options as a fallback.
4. WHEN the currently selected period is removed from `enabled_periods`, THE Android_App SHALL automatically switch to the first available enabled period.

---

### Requirement 23: Wire Project Child Chit Picker

**User Story:** As a user managing a project, I want to pick an existing chit to add as a project child using a searchable picker, so that I do not have to manually type chit IDs.

**Covers:** W429 `openAddChitModal()`

#### Acceptance Criteria

1. WHEN the user taps "Pick Chit" in the ProjectsZone, THE Android_App SHALL open the ChitPickerSheet with search functionality.
2. THE ChitPickerSheet SHALL allow the user to search chits by title and select one to add as a child of the current project.
3. WHEN a chit is selected, THE Android_App SHALL add it to the project's `child_chits` list and update the UI immediately.
4. THE ChitPickerSheet SHALL exclude chits that are already children of the current project from search results.

---

### Requirement 24: Create New Child Chit from Project

**User Story:** As a user managing a project, I want to create a new chit pre-configured as a child of the current project, so that I can quickly add new items to a project without manual setup.

**Covers:** W431 `createNewChildChit(event)`

#### Acceptance Criteria

1. WHEN the user taps "Create New" in the ProjectsZone, THE Android_App SHALL create a new Chit with the current project's ID set as its parent project.
2. THE new Chit SHALL be added to the current project's `child_chits` list.
3. WHEN the new Chit is created, THE Android_App SHALL navigate the user to the editor for the new Chit.

---

### Requirement 25: Recurrence Scope Selection for Edits (Existing Enhancement)

**User Story:** As a user editing a recurring chit, I want to choose whether my edits apply to this instance, this and future instances, or all instances, so that I have full control over recurrence modifications.

**Covers:** Supports W314, W315, W368 scope selection patterns

#### Acceptance Criteria

1. WHEN a user saves changes to a Virtual_Instance, THE Android_App SHALL display a scope selection dialog with options: "This instance only," "This and all future instances," and "All instances."
2. WHEN "This instance only" is selected, THE Android_App SHALL save the changes as a Recurrence_Exception for that date.
3. WHEN "This and all future instances" is selected, THE Android_App SHALL modify the Recurring_Chit's rule or create a split point at the selected date.
4. WHEN "All instances" is selected, THE Android_App SHALL modify the parent Recurring_Chit directly.

---

### Requirement 26: Quick Reminder Creation

**User Story:** As a user, I want to create a quick reminder (a chit with a notification at a specific time) from the Quick Alert Sheet, so that I can set time-based reminders without opening the full editor.

**Covers:** W117 `_quickReminderSave(data, andView)` (detailed behavior)

#### Acceptance Criteria

1. WHEN the user selects "Reminder" type in the Quick_Alert_Sheet, THE Android_App SHALL display fields for: reminder text, date, and time.
2. WHEN the user saves a reminder, THE Android_App SHALL create a new Chit with the entered text as the title, the selected date/time as the due date, and a notification alert configured for that time.
3. THE reminder Chit SHALL appear in the Tasks view and Calendar view at the specified date/time.
